# 开发文档（docs/development.md）

## 一、背景与目标

外贸业务员在收到陌生询盘时，信息有限、时间有限，难以逐一核查客户真实性，容易在被骗样品费、验厂费或货款（尤其是邮箱被仿冒后的 BEC 转账）上遭受损失。本项目把零散信息转化为一份**有来源依据、结构固定**的风险报告，帮助业务员决定"该追问什么、该索要什么材料、收款方式是否安全"。

**目标用户**：外贸业务员（非技术用户），在支持 Agent Skill 的客户端中使用，无需自行安装工具。

**核心边界**：定位是「风险信号筛查 + 证据整理」，不是判定对方是不是骗子；输出只给风险等级与依据，不做定性指控。

## 二、范围

| 版本 | 内容 | 状态 |
| --- | --- | --- |
| MVP（V1） | 公司公开痕迹、域名与官网、联系方式一致性、询盘行为红旗、负面信息检索 | 已交付 |
| V2 | 接入各国企业注册库（OpenCorporates、Companies House 等）与制裁名单 API；红旗清单扩充至 20+ 条 | 规划中 |
| V3 | 营业执照/合同 PDF 元数据与版式异常、证书编号反查、付款水单可信度提示（仅作提示） | 规划中 |

**明确不做**：法律意见、投资尽调、刑事侦查、个人隐私挖掘（住址、家庭、私人社交账号）。

## 三、调研与参考

开发前检索了社区中同类 Agent Skill，主要借鉴两个成熟案例：

| 案例 | 借鉴点 |
| --- | --- |
| `mtjikuzu/hermes-osint-skill` | 分阶段方法论、批判性红旗目录、来源文档化（链接 + 访问时间）、Verification Checklist、`references/` + `scripts/` 的目录组织；「无结果 ≠ 干净」的表述纪律 |

同时对齐 Agent Skill 通用规范：`SKILL.md` 带 `name` / `description` frontmatter，详细知识拆到独立文件，脚本输出 JSON 便于模型解析。

## 四、架构设计

### 4.1 五步流程

1. **采集**：整理用户提供的信息，列出缺项；缺关键信息只问一次。
2. **并行检索**：四个模块独立执行，单项失败不影响其他项。
3. **交叉比对**：重点找矛盾（官网国别 vs 电话区号 vs 注册地址 vs 发件域名）。
4. **打分定级**：严格按 `red_flags.md` 累加权重。
5. **出报告**：按 `report_template.md` 输出。

### 4.2 检查模块

| 模块 | 检查内容 | 版本 |
| --- | --- | --- |
| 1. 公司真实性 | 是否在官方登记；注册时间/地址/法人；地址是否虚拟办公室 | MVP 公开检索 |
| 2. 域名与官网 | WHOIS/RDAP、DNS、官网是否抄袭、是否仿冒知名公司域名 | V1 |
| 3. 联系方式一致性 | 免费邮箱 vs 企业域名、Reply-To 一致性、区号与声称国家 | V1 |
| 4. 询盘与交易行为红旗 | 按 `red_flags.md` 逐条判断，引用原文依据句 | V1 |
| 5. 负面信息检索 | 公司名/域名/邮箱 + scam/fraud/投诉；制裁名单 | V1 |
| 6. 材料真伪辅助 | 证书编号反查、PDF 元数据、水单提示 | V3 |

每个模块统一输出：检查项、结果（正常 / 可疑 / 无法核实）、证据（来源链接 + 检索时间）。

## 五、关键设计决策

| 决策 | 理由 |
| --- | --- |
| 红旗用编号（`RF-<类别>-<序号>`）而非仅描述 | 可引用、可统计、可扩展；发布后编号不复用、不改含义 |
| 评分由 `red_flags.json` 确定性计算，不做模型临场判断 | 保证同一输入多次运行结果一致、可复现（验收 A6） |
| 查不到统一输出「未查到」/`status: "unavailable"` | 防幻觉，避免用印象补数据 |
| 报告固定附免责声明、敏感信息脱敏 | 合规与隐私要求（验收 A5、A7） |
| Python 与 Node 双实现 | 文档要求 Python；Node 版本用于无 Python 环境时的本地验证，两者逻辑同构 |
| 脚本支持 `--rdap-json` 离线 fixture | 使域名类判定可离线测试（验收 A3），不依赖实时网络 |

## 六、验收用例（tests/cases/）

| 用例 | 场景 | 期望 | 运行方式 |
| --- | --- | --- | --- |
| A1 | 询盘要求先付验厂费 | 命中 RF-PAY-001，等级「高」、总分 5 | 离线（评分器） |
| A2 | 域名 `app1e.com` | 识别为 homoglyph 仿冒 Apple | 离线（相似度） |
| A3 | 域名注册不足 6 个月 | `is_new_domain = true` 并给出注册日期 | 离线（RDAP fixture） |
| A4 | 查不到任何信息 | 等级「需人工核实」，不编造 | 离线（评分器） |
| A5 | 样例报告 | 每条结论带来源 + 检索时间 + 免责声明 | 离线（结构检查） |
| A6 | 同一输入连续评分 | 3 次等级与总分一致 | 离线（评分器） |
| A7 | 银行账号脱敏 | 仅保留后 4 位 | 离线（工具函数） |

运行：

```bash
node tests/run_cases.mjs
```

## 七、扩展方式

- **新增骗局套路**：在 `red_flags.md` 追加「编号、红旗、判断标准、权重」，同步更新 `scripts/red_flags.json` 与 `CHANGELOG.md`，并在 `tests/cases/` 增加用例。
- **新增品牌**：在 `scripts/brands.json` 的 `brands` 数组追加条目。
- **新增数据源**：在 `data_sources.md` 登记入口与降级做法。

## 八、路线图

1. 红旗清单扩充至 20+ 条，覆盖更多行业特有骗局。

3. 增加材料真伪辅助模块（V3）。
4. 补充多语言报告模板（英文询盘场景）。
