概述

本文档定稿 buyer-check 从 v0.4.0 到 v0.6.0 的迭代方案，开发 agent 按本文执行即可；除标注“待确认”的条目外，均已由产品负责人确认。仓库为 github.com/MysticRichard/buyer-check（公开）。

现状评估结论： 核心功能与最初目标一致：定位为风险信号筛查而非定论、五步流程、MVP 六项功能、确定性评分、脱敏、命名规范均已落地，9 个验收用例全部通过。需要修正的是五件事：

编号

主题

决策

D1

仓库与隐私

比赛要求仓库公开，因此保持公开并彻底脱敏：删除真实客户报告、重写 Git 历史，只保留合成样例

D2

分数口径

保留 0–100 的风险分，以等级为准、分数辅助；分数区间与等级对齐，让用户一眼分辨高低

D3

需人工核实

分数条变灰色，旁边固定标注「低置信度，分数仅供参考，还需要更多信息实际核实」

D4

输出模式

一次检索、两种输出：默认出结论卡，完整报告按需生成

D5

结论卡

只显示、不落盘；风险分与风险等级都要醒目突出；风险点简洁明了

D6

追问话术

委婉含蓄，不让对方察觉真实意图；英文为主，附一句中文含义

D7

计分原则

查不到只降置信度、不加风险分；只有“积极矛盾”才计分

D8

人机分工

按环境能力分三档（一步到位、半自动、纯人工）；LinkedIn、Facebook 需保持登录态，未登录则跳过该项并标注

D9

点开链接类核实

地图、海关、社媒：能一步到位就一起调查，不行就由 Skill 给链接加清单、业务员回传要点

D10

海关数据

优先使用免费平台；没有免费公司级数据的国家直接跳过，不扣分

D11

使用者与市场

使用者很多、客户遍布全球：核心能力全球通用，按国家增强的部分做成国家适配层

D12

试点国家

优先中东、东南亚

D13

话术语言

默认英文加中文含义；非英语国家的语言选项后续版本再做

边界与硬性约束

以下约束写入 SKILL.md 与 README.md，任何版本都不得放宽；使用者遍布全球，边界比功能更重要。

类别

约束

查询对象与目的

对象仅限商业询盘中的对方，目的仅限识别交易风险；不得用于查个人、跟踪或人肉

个人资料范围

只看职业身份相关的公开资料：职位、任职公司、行业、账号是否真实。不看家庭、住址、私人照片和与生意无关的动态，不做个人画像

电话号码

只检索对方在询盘里主动给出的号码，目的仅两个：找诈骗投诉记录、找对应的商业身份

禁用工具

不使用按用户名或邮箱枚举各网站账号的工具（Sherlock、Maigret、Holehe 一类）

数据不外传

检索与报告都在用户自己的环境完成；Skill 不收集、不上传用户数据，不做遥测；README 明示这一点

平台与登录

不绕过登录、验证码、付费墙，不批量抓取。一步到位模式只使用用户自己的登录态，只读、一次打开一个主页、低频，并在首次使用时说明由用户授权。多数注册库禁止自动化批量下载，因此对注册库只给链接和检索清单，不自动抓取

个人信息显示

个人姓名、邮箱、电话在卡片和报告中默认脱敏（如 d***e@gmail.com），用户明确要求才显示全称

敏感信息

用户贴入的银行账号、证件号仅用于本次分析，不写入任何文件，报告中脱敏显示

防幻觉

没有来源的内容不写成事实；每条事实带来源链接与检索时间；来源矛盾时如实并列；不推断对方主观意图；未覆盖的维度写“未覆盖”，不写“正常”

合规措辞

不使用“骗子”等定性字眼，用“风险较高”“命中多项诈骗常见特征”；报告与卡片固定附免责声明，不构成法律意见

开源许可

仓库为 MIT 协议。不引入 GPL 代码（如 PhoneInfoga）；不打包非商业授权的数据（如 OpenSanctions 数据）；新增任何依赖前核对许可与维护状态，并记录在“第三方项目与数据源选用”一节

LinkedIn 提醒

浏览个人资料会让对方看到访问记录，一步到位模式开始前必须提醒业务员先在 LinkedIn 隐私设置里把“个人资料查看选项”调为私密模式（入口以平台当前界面为准）

需人工核实的显示（D3）

分数条用灰色，不使用绿、黄、红。

分数旁固定标注：「低置信度，分数仅供参考，还需要更多信息实际核实」。

卡片给出信息增益最大的一项补充信息，例如“补充企业邮箱，置信度可从低提升到中”。

待确认规则（建议默认实现，负责人确认后固化）： 现有实现中，身份锚点全缺会覆盖一切，即使命中了“要求先付款”也只显示“需人工核实”，会把严重信号藏在灰色里。建议改为：T ≥ 8 或命中权重 5 红旗时，等级仍显示“高”（红色），同时标注“置信度低”；其余情况身份锚点全缺才显示“需人工核实”。

结论卡版式

第一行永远是“颜色 + 等级 + 分数”，用二级标题，字号最大；分数条为 10 格，按 round(分数 / 10) 填充，灰色状态用 ▒ 填充；整张卡不超过约 25 行；风险点最多 5 条，按严重程度排序，每条只有“符号 + 红旗名（编号）+ 一句证据”。符号含义：🔴 命中权重 4 以上，🟡 命中权重 3 以下，🟢 已排除，⚪ 未查到或未覆盖。

追问话术规则（D6、D13）

用常规业务流程当理由，如“我们的标准流程”“为了团队统一建档”“财务要求”；不出现“核实”“背调”“怀疑”“诈骗”等词。

每条话术只索要一样东西，不一次问一串。

询盘期不索要营业执照，只索要官网、企业邮箱、具体型号和数量等；执照在订单前阶段才索要。

不拒绝、不指责；对方提出不合理要求时，用“我们的流程是……”把话题带回正常轨道。

话术必须对应命中的红旗或缺失的线索，不凭空提问；每条最多附一行只给业务员看的提示，说明目的与如何判读对方的回应；一张卡最多 3 条。

英文为主，每条附一句中文含义；业务员回传客户回复后，Skill 只更新变化的维度并重新出卡，可再追加最多 3 条话术（增量复核）。

核实体系

核实围绕“身份链”展开：人、公司、官网、邮箱之间的指向关系闭合得越完整、来源越独立，置信度越高；查不到只降置信度，积极矛盾才计分（D7）。首个询盘常常只有名称加电话，因此起手流程从这两项出发，逐步扩展线索。

身份链与置信度

节点是人（姓名、电话、社媒）、公司（名称、地址）、官网域名、邮箱；边是证据，即“谁指向谁”。闭合度对应现有的置信度三档，不改变卡片与评分。

名称加电话的起手流程

电话号码本身：解析国家区号、有效性、类型（手机、固话、网络电话），与自称国家对比。纯本地计算，由脚本完成。

业务员采集聊天软件资料：WhatsApp 的商业资料（网站、邮箱、地址、行业）、头像、简介；Facebook 主页及页面创建时间、管理员所在国家。Skill 给出固定的采集清单。

公开检索：号码的几种常见写法加 scam、fraud 检索；号码是否出现在 B2B 平台、地图商家页、公司官网联系页；名称是公司则查名录，是个人则查 LinkedIn 公开摘要，看任职公司。号码与名称出现在同一来源，才算强关联。
